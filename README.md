# ZakupAI

Первая рабочая версия для проверки оформления совместных закупок. Заказы и оплаты сохраняются в базе. Реализованы кабинет организатора, каталог, корзина, отслеживание заказа, ручное подтверждение поступлений и сводка на выкуп.

**Локальный запуск**

Нужен Node.js 24 или новее. Из папки `web`:

```sh
npm run install:ci
npm run build
```

На новой локальной базе один раз примените начальную миграцию:

```sh
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_material_sentinel.sql
```

Не повторяйте применённую миграцию. Новые изменения схемы создаются отдельными миграциями через `npm run db:generate` и применяются по порядку. Файлы применённых миграций не меняются.

```sh
npm run dev -- --port 5173
```

Откройте `http://127.0.0.1:5173/`. В локальном режиме стартовый проект имитирует вход в ChatGPT через `/signin-with-chatgpt?return_to=/`. Эта имитация не попадает в рабочую сборку.

После входа можно создать пустое пространство или открыть пример. Демо добавляется отдельным действием, содержит вымышленные заказы и помечается в интерфейсе. Локальная база находится в игнорируемой `.wrangler/state/`, она отдельна от размещённой базы.

**Проверки**

```sh
npm test
npm run typecheck
npm run test:http
```

Последняя команда требует работающий локальный сервер и демо-пространство. Она добавляет тестовый заказ, проверяет поступление, временно закрывает и снова открывает демо-закупку. На обычном рабочем пространстве тест отказывается запускаться. Для другого локального адреса задайте `ZAKUPAI_TEST_URL`.

Проверки базы используют SQLite и ту же сгенерированную SQL-схему. HTTP-проверка дополнительно выполняется через локальный Worker и D1. Визуальная проверка в браузере не выполнена: инструменту не предоставлен доступ к браузеру.

**Основные маршруты**

| Адрес | Назначение |
|---|---|
| `/` | Кабинет организатора, требует входа |
| `/c/{id}` | Каталог одной закупки |
| `/order/{token}` | Состояние одного заказа по случайной ссылке |
| `/api/workspace` | Данные и настройки пространства текущего владельца |
| `/api/checkout` | Создание заказа покупателем |
| `/api/export` | Выгрузка текущего владельца, требует входа |

На приватном Site платформа дополнительно ограничивает доступ к любому маршруту владельцем Site. Прикладная проверка владельца остаётся обязательной на всех административных API. Доступ к публичному заказу требует случайный 256-битный токен; номер заказа сам по себе его не открывает.

**Размещение**

Sites использует `.openai/hosting.json`, D1-привязку `DB` и Worker из `dist/server/index.js`. Идентификатор Site сохранён в манифесте. Секреты и локальные базы не добавляются в Git. Аудитория опубликованной версии остаётся приватной.

Эта версия предназначена для проверки на тестовых данных. До реального пилота нужно согласовать бизнес-правила, выбрать боевую инфраструктуру для данных клиентов, реализовать недостающие операции и проверить интерфейс на телефонах.
