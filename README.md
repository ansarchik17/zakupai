# ZakupAI

Кабинет для совместных закупок: каталог, корзина, заказы, ручное подтверждение оплат, выдача и сводка на выкуп. Покупателям регистрация не требуется.

## Аккаунты и администрирование

- `/login` — вход администратора и организаторов по email и паролю.
- `/admin` — список организаторов, приглашения, отключение доступа и восстановление пароля. Сервер разрешает доступ только активному администратору.
- `/invite/{token}` — принятие приглашения или смена пароля. Ссылка действует 24 часа, используется один раз, может быть отозвана. В базе хранится только её хеш.
- `/` — закупки текущего пользователя. Организатор получает отдельное пространство при принятии приглашения.
- `/c/{id}` и `/order/{token}` — оформление и просмотр заказа покупателем без аккаунта.

При отключении организатора его сессии и ссылки восстановления отзываются сразу. Заказы и оплаты сохраняются. После повторного включения нужен новый вход. Администратор не может отключить себя. Он управляет доступом, но не получает пароль, сессию или ссылку восстановления организатора. Восстановление отправляется только на сохранённый email владельца через настроенную почту. Пока SMTP не подключён, эта операция недоступна. Ошибка отправки отзывает ссылку; прежние ручные ссылки восстановления больше не принимаются.

Пароли хранятся как scrypt-хеши с индивидуальной солью (N=32768, r=8, p=3). Сессии — случайные 256-битные токены, в базе только SHA-256-хеши. Cookie имеет HttpOnly, SameSite=Lax и Secure при HTTPS, срок 30 дней. Ограничение попыток входа хранится в D1. Публичной самостоятельной регистрации организаторов нет.

Сайт открыт для перехода по ссылке без входа в ChatGPT. Кабинеты требуют собственную сессию email/пароль; административные права проверяются сервером. При успешном входе администратора его прежнее пространство из доверенной идентичности Sites/локального просмотра привязывается к новому аккаунту, если у него ещё нет пространства. Данные закупок при этом не меняются.

## Локальный запуск

Нужен Node.js 24+. В папке приложения:

```sh
npm run install:ci
npm run local
```

Сервер слушает loopback и выбирает свободный порт начиная с 3000. Другой начальный порт: `npm run local -- --port 3100`. Миграции применяются автоматически. База хранится в `.wrangler/localhost/`, прежняя база стандартного просмотра `.wrangler/state/` остаётся отдельно. Для изолированной проверки можно задать `ZAKUPAI_LOCAL_STATE_DIR`.

При новом клонировании настройте начального администратора. `npm run admin:configure` принимает одну строку JSON через скрытый stdin с полями `email`, `password` (10–128 символов) и необязательным `name`. Открытый пароль не сохраняется. Команда записывает email и scrypt-хеш в игнорируемый `.dev.vars` с правами 0600. Не передавайте пароль в аргументах командной строки и не добавляйте `.dev.vars` в Git.

Аккаунт администратора создаётся при первом запросе входа из `ZAKUPAI_ADMIN_EMAIL`, `ZAKUPAI_ADMIN_PASSWORD_HASH`, `ZAKUPAI_ADMIN_NAME`. Повторный запуск не меняет пароль существующего аккаунта и не повышает роль существующего организатора. После настройки перезапустите сервер. Для опубликованной версии эти значения задаются отдельно в runtime secrets Sites.

## Приглашения и SMTP

Приглашения работают без почтового провайдера: администратор создаёт ссылку, копирует её и передаёт организатору. Ссылка показывается только при создании; повторное приглашение на тот же email отзывает предыдущее. Флажок отправки письма доступен после подключения почты. Ошибка отправки отображается явно, ссылка остаётся доступной.

Cloudflare Worker обращается к почтовому реле по HTTPS. Непосредственное подключение к SMTP выполняет отдельный Node-процесс с Nodemailer. Это позволяет использовать обычный SMTP-сервер с TLS, не помещая SMTP-пароль в приложение или браузер.

Для локальной почты:

1. Скопируйте `.env.smtp.example` в `.env.smtp` и задайте сервер, пользователя, пароль и подтверждённого отправителя. Порт 465 использует TLS, 587 — обязательный STARTTLS.
2. Создайте случайный `SMTP_RELAY_TOKEN` длиной минимум 32 символа.
3. В `.dev.vars` задайте тот же токен и `SMTP_RELAY_URL=http://127.0.0.1:3025/send`.
4. Запустите `npm run mail:relay` отдельно от сайта и перезапустите сайт.

Для размещённой версии реле нужно запустить на сервере за HTTPS и задать его URL/токен в runtime secrets Sites. `ZAKUPAI_PUBLIC_URL` при необходимости задаёт канонический origin ссылок. SMTP-пароль и адрес отправителя остаются только на сервере реле. Наличие переменных не подтверждает доставку: она проверяется реальной отправкой после предоставления настроек провайдера.

## Проверки

```sh
npm test
npm run typecheck
npm run build
```

Unit-тесты используют SQLite с теми же миграциями, что D1. Покрыты роли, хеширование, сессии, одноразовые ссылки, конкурентное принятие, отключение, восстановление, лимиты входа и исходные правила заказов/оплат.

`npm run test:auth:http` проверяет полный сценарий через локальный Worker/D1. По умолчанию ожидает тестовый сервер на порту 3200; другой адрес задаётся `ZAKUPAI_TEST_URL`. Скрипт принимает email/пароль тестового администратора через скрытый JSON stdin и создаёт тестовых организаторов и заказы. Запускайте на отдельной локальной базе, например с `ZAKUPAI_LOCAL_STATE_DIR=.wrangler/auth-smoke`.

`npm run test:http` проверяет исходный цикл заказа. Требует `ZAKUPAI_TEST_EMAIL`, `ZAKUPAI_TEST_PASSWORD` и аккаунт с демо-пространством; иначе отказывается создавать тестовые заказы. Не используйте реальные клиентские данные для этих проверок.

## Размещение и границы

Сайт использует React/TypeScript, Vinext, Cloudflare Worker и D1. Идентичность Sites сохранена в `.openai/hosting.json`. Миграции схемы добавляются через `npm run db:generate`; применённые файлы не редактируются. Bootstrap и демонстрационные данные не входят в миграции.

По разрешению владельца аудитория Site открыта по ссылке. Каталог и приглашения открываются без аккаунта ChatGPT. Кабинеты и административные API защищены собственными сессиями, проверкой роли и владельца пространства. Приглашённый человек принимает приглашение и задаёт пароль самостоятельно; администратор проверяет вход только на собственных тестовых аккаунтах.

Банковской интеграции, автоматических WhatsApp-уведомлений, возвратов и ИИ пока нет. Интервью, замеры и реальный пилот остаются отдельным этапом. Система приглашений не подтверждает готовность остальных процессов к коммерческой эксплуатации.
